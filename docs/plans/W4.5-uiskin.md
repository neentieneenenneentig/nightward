# W4.5 — Pixel UI skin (brief, 2026-07-10)

> **SUPERSEDED (2026-07-17) by U1 — Lens UI Unification.** The user loves the Lens
> aesthetic (dark, monospace, technical) and wants ALL panels to use it instead of
> a procgen pixel-art 9-slice. See `docs/plans/U1-lens-ui-unification.md` for the
> replacement plan. This brief is kept as a record of the approach.

> User verdict: the game needs an "awesome polished feel", and the modern-flat DOM UI
> (rounded corners, backdrop blur, gradients) clashes with the hi-bit pixel world. Re-skin
> the chrome so the UI looks like it was carved out of the same dream as the terrain.

## The decision: procgen 9-slice, not an off-the-shelf kit
Pixel CSS kits exist (NES.css, RPGUI, PSone.css) and were considered — rejected:
- They lock into someone else's aesthetic (NES.css is literally 8-bit Nintendo chrome);
  our world is seeded hi-bit, and the UI should share ITS palette, not Mario's.
- They ship fonts/assets and their own class systems — fights both the **100% procgen**
  non-negotiable and our existing `.nw-*` DOM structure.
- We already have the winning tool: seeded canvas generators (`engine/procgen/*` makes
  sprites and icon data-URIs today). UI chrome is just one more generator.

## Where things are today (read these first)
- `src/game/ui/styles.ts` (231 lines) — ALL the CSS, injected once via `injectStyles()`.
  CSS vars at the top (`--panel`, `--panel-edge`, `--ink`, `--gold`, `--good`, `--bad`).
- `src/game/ui/ui.ts` — builds the DOM chrome once; panels rebuilt while open. Class map:
  `.nw-badge` (top bar chips), `.nw-btn` (action bar), `.nw-panel`/`.nw-phead`/`.nw-row`
  (panels), `.nw-buildbar`, `.nw-gather`/`.nw-gbar`, `.nw-hpbar`, toasts in `ui/toast.ts`.
- `src/engine/procgen/icons.ts` — the existing canvas→data-URI pattern to copy
  (`iconUrl(id, kind)` bakes once, caches, returns `canvas.toDataURL()`).

## Spec
### 1. `engine/procgen/uiskin.ts` — the chrome generator (new file)
- `panelUrl(seed, variant)` → data-URI of a small (e.g. 24×24 @ 3px slice) pixel 9-slice:
  dark parchment/iron fill, 1px highlight + 1px shadow bevel edges, corner rivets/notches.
  Variants: `panel`, `button`, `button-primary`, `button-danger`, `bar` (trough for hp/xp).
  Bake once per variant at boot (same seed as the world so the UI is part of the dream).
- Colors: derive from a tiny palette table in the generator (hand-picked hi-bit hues that
  sit with the world art) — NOT random per seed; seed only jitters texture/noise so it
  stays readable. Keep them as exported consts so `styles.ts` vars can match.
### 2. `styles.ts` rewrite — same classes, pixel skin
- `border-image: url(<panelUrl>) 3 fill / 3px stretch` (or `round`) on `.nw-badge`,
  `.nw-btn`, `.nw-panel`, `.nw-buildbar`, `.nw-gather`, toast — kill `border-radius`,
  `backdrop-filter`, gradients.
- `image-rendering: pixelated` everywhere chrome or icons render; icons already pixelate.
- Font: **no font files** (procgen rule). Get the chunky feel from the system monospace
  stack + `text-transform: uppercase`, tight `letter-spacing`, 1px `text-shadow` bevel,
  and small caps sizes (11–12px). If the user wants a true bitmap font later, that's a
  separate decision (committed OFL font file = new kind of asset — needs their sign-off).
- Bars (hp/gather/xp): step the fill in pixel chunks (`width` snapped to 4px increments,
  hard color bands instead of gradients) so meters read as segmented pixel bars.
### 3. Touch nothing else
- No layout moves, no new panels, no logic edits in `ui.ts` beyond class/var tweaks if
  a style hook is missing. This is a skin, and it must stay diffable as one.
