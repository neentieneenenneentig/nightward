# R1.5 — The Painted World (look & depth pass)

Goal: the world currently reads as a flat checkerboard of colored squares (R1 gate verdict:
"kinda looks disappointing currently tbh"). This milestone makes it read as a *place* — soft
material borders, a sense of elevation, grounded objects, living water — **without changing
what a tile IS**. Square topology stays; nothing in `wasm/nightward-core` changes; this is pure
rendering + data.

This brief is implementation-grade; the **Acceptance checklist** at the bottom is the post-merge
verification contract — run it verbatim. Prereq: R1 merged (`v0.13-r1-writable-world`) —
`world.materialAt` (override-aware), `WorldCore`/`ChunkMap.rebakeTiles`, the god brush.

## The one big idea (learning sidebar)
Two cheap tricks fake depth on a flat grid: **dual-grid autotiling** (a border only looks hard
because nothing acknowledges the pixel is *between* two materials — sample both neighbors and
blend) and **painter's-algorithm shading** (a strip that's darker below and lighter above a
boundary reads as a step, with zero geometry — the eye infers the ledge from shading alone,
the same trick Zelda/Stardew use). Both are baked once per chunk, same as everything else —
"looks 3D" is a *rendering* property, not a topology property.

export interface MaterialDef {

**Legibility re-ramp (playtest flag: DIRT vs MUD near-identical).** Re-ramp three rows, keep the
original 9 biome hues untouched:
- **DIRT** → lighter/dry/tan (dust): `ramp('#7a5f3f', '#93764f', '#ac8f64')`, detail stays `speckle`.
- **MUD** → darker/cooler/wet: `ramp('#241c12', '#33281a', '#443423')`, detail becomes new `wet`
  (glossy streak highlights + dark pooled specular dots — reads "wet" at a glance, not just "dark").
- **TILLED** → ramp unchanged (`'#4a3928','#5a4632','#6e5740'` — already distinct from the new DIRT/MUD),
  detail becomes new `furrows` (evenly-spaced plowed rows) instead of `cracks` (cracks now reads
  as ICE's signature, TILLED shouldn't share it).

⚠ **Landmine, do not touch:** rows 0–8's `name` field (`'deep'|'water'|'sand'|...`) is a live lookup
key — `WorldGen`'s `featTable` builds from `FEATURES[i].density[material.name]` (features.ts's
density objects are keyed by these exact lowercase strings). Renaming/capitalizing them silently
zeroes every feature spawn density. The build-rejection toast (below) capitalizes **for display
only**, via a local `cap()` helper — the data string itself never changes.

## `src/engine/procgen/sprites.ts` — two new `Detail` kinds
```ts
export type Detail =
  | 'none' | 'grass' | 'flowers' | 'speckle' | 'waves'
  | 'forest' | 'cracks' | 'pebbles' | 'sparkle' | 'wet' | 'furrows';
```
Add matching cases to `makeTileVariants`'s detail switch:
- `'wet'`: 3 short glossy highlight streaks (`lighten(light, 22)`, 3-4px) + 2 small puddle dots
  (a `darken(dark,18)` center pixel with a `lighten(light,16)` rim pixel).
- `'furrows'`: horizontal ridge lines every ~7px (`for (row = 3; row < 32; row += 7)`), each row a

  via `hash2(x, row, seed^biomeId)` so rows aren't perfectly straight.

## `src/game/world/art.ts` — new drawing primitives
Three additions, all pure functions of (material, tile coords, existing deterministic hashing) —
no new RNG concepts:
1. **`feather(ctx, m, ntx, nty, edge, px0, py0)`** — the dual-grid transition painter. Takes the
   *neighbor's* material `m` and its own tile coords (so it picks the same variant that would
   actually bake there — `this.tile(m, ntx, nty)`), and draws a ~10px feathered band of that
   texture across the shared edge into the destination tile at `(px0,py0)`, using 4 alpha-stepped
   strips (`0.55 → 0`) so the border reads as a soft gradient of the *neighbor's real texture*,
   not a flat color blend.
2. **`shadow(ctx, cx, cy, rx, ry, alpha)`** — soft radial-gradient blob (dark center → transparent
   edge), used for contact shadows under features/buildings/entities. One shared helper, not
   duplicated per caller.
3. **`foamFrame(seed, frame: 0|1|2): HTMLCanvasElement`** — small transparent-background canvas of
   pale foam flecks (`lighten` of the water ramp toward near-white), one of 3 deterministic
   variants keyed by `frame` (different hash offset per frame, NOT random — same frame index
   always looks the same on every bake, only the *displayed* frame index is time-driven).

## `src/game/world/chunkmap.ts` — the bake passes
`bake()` gains two new passes after the existing ground pass, plus shadows folded into the
existing feature pass, plus an optional foam overlay:

1. **Transition pass** (dual-grid, item 1): for every tile, check its 4 neighbors (N/E/S/W). A
   neighbor "outranks" the tile if `heightClass[neighbor] > heightClass[tile]`, or on a tie,
   `neighborMatId > tileMatId` (arbitrary but deterministic and symmetric-safe — exactly one side
   of any differing border draws). If the neighbor outranks, call `art.feather(...)` to paint that
   neighbor's texture feathering onto this tile's edge. Skip identical-material neighbors entirely
   (most of the map — cheap).
2. **Cliff pass** (pseudo-3D ledges, item 2): for every tile, if
   `heightClass[thisTile] > heightClass[southNeighbor]`, draw a darker strip along the tile's
   south edge (`ctx.fillRect`, ~7px tall, color `darken(ramp[0], 35)`; if the height *gap* is ≥2,
   widen to ~10px and darken further) plus a 2px `lighten(ramp[2], 30)` highlight line at the strip's
   top (the sunlit rim). Colored from the material's *own* ramp so grass cliffs, hill cliffs, and
   mountain cliffs each look distinct.
3. **Contact shadows** (item 3): in the existing feature-draw loop, before `ctx.drawImage(img, ...)`,
   call `art.shadow(...)` centered on the sprite's foot anchor (same x as the sprite draw, y at the
   sprite's bottom edge), sized ~35% of the sprite's width. One extra draw per feature tile only.
4. **Foam overlay** (item 4, water life): after the base bake, check if the chunk contains any
   `WATER`/`SHALLOW`/`DEEP` tile adjacent to a non-water-family tile (a shoreline chunk). If so,
   bake 3 extra small transparent overlay canvases (one per foam frame, foam pixels only at
   shoreline tile edges) → 3 extra `Texture`s → one extra `Sprite` added to `this.layer`
   immediately after the chunk's base sprite (renders on top; insertion order = draw order in the
   unsorted `ground` layer). Store as `chunks.get(key).foam = { sprites: [tex0,tex1,tex2], view: Sprite }`.
   Chunks with no shoreline get `foam: null` — zero extra cost for 95% of the map.

**New `tickFoam(nowMs: number)`** on `ChunkMap`: `frame = Math.floor(nowMs / 200) % 3` (5 Hz,
the ROADMAP's cap), and for every loaded chunk with `foam`, set `view.texture = foam.texs[frame]`
if the frame actually changed since the last call (skip redundant reassignment). Called once per
render frame from `main.ts`'s `render()`. **This is the reusable mechanism note for R2:** the
generic hook is "a chunk may own a secondary overlay sprite/texture, independent of the base bake,
updated on its own cadence." R2's fire glow follows the same `{sprite, tex}`-per-chunk-overlay
shape but re-renders continuously from live fuel/burn fields instead of swapping 3 pre-baked
frames — don't invent a second mechanism, extend this one.

### Rebake dedupe — extend, don't fork (load-bearing per ROADMAP)
The dual-grid transition pass and the cliff pass both read a tile's neighbors, which may live in
an **adjacent chunk** across any of the 4 borders (not just south, unlike the existing tree-poke
rule). Replace the south-only special case in both `rebakeTile` and `rebakeTiles` with one shared
private helper:
```ts
private dirtyFor(tx: number, ty: number, dirty: Set<string>) {
  const cx = Math.floor(tx / CHUNK), cy = Math.floor(ty / CHUNK);
  const lx = ((tx % CHUNK) + CHUNK) % CHUNK, ly = ((ty % CHUNK) + CHUNK) % CHUNK;
  dirty.add(cx + ',' + cy);
  if (ly === 0) dirty.add(cx + ',' + (cy - 1));           // north chunk: tree-poke (existing) + feather/cliff dependency
  if (ly === CHUNK - 1) dirty.add(cx + ',' + (cy + 1));   // NEW: south chunk's north-edge feather
  if (lx === 0) dirty.add((cx - 1) + ',' + cy);           // NEW: west chunk's east-edge feather
  if (lx === CHUNK - 1) dirty.add((cx + 1) + ',' + cy);   // NEW: east chunk's west-edge feather
}
```
Both `rebakeTile(tx,ty)` and `rebakeTiles(tiles)` build their dirty-set through this one function
(the loop bodies otherwise unchanged — still skip unloaded chunks, still rebuild each dirty chunk
at most once). No diagonal-corner case needed — the feather pass only samples N/E/S/W neighbors,
never diagonals, so corner chunks are never a dependency.

### Test-only debug hook
`ChunkMap` gains `debugPixel(tx, ty, offX = 16, offY = 16): [number,number,number,number] | null`
— reads one pixel from a loaded chunk's baked canvas (via `(tex.source as any).resource` — the
underlying `HTMLCanvasElement` Pixi wraps) at tile-local pixel offset `(offX,offY)` (default:
tile center). Returns `null` if the chunk isn't loaded. This is the acceptance checklist's probe
for "is there actually a blended/darkened/shadowed pixel here" without eyeballing every check.
Also add `hasFoam(tx, ty): boolean`. Expose `chunks` on `__nw` in `main.ts` (alongside `core`,
`world`, etc.) so these are reachable from the console.

## `src/game/systems/build.ts` — name the blocking material (rider fix)
`placeError()` currently ends in a generic "Blocked ground — can't build on water, rock or another
building" regardless of cause. Rewrite to check in the same order as `world.canPlaceAt` and name
the specific blocker:
```ts
private placeError(): string {
  const m = this.mode!;
  const { state, world } = this.ctx;
  if (!invHasAll(state, m.def.cost)) return 'Not enough materials';
  if (world.buildingAt(m.tx, m.ty)) return "Something's already built there";
  const f = world.featureAt(m.tx, m.ty);
  if (f && f.blocking && !world.isDepleted(m.tx, m.ty)) return `Blocked by ${f.name} — clear it first`;
  const mat = MATERIALS[world.materialAt(m.tx, m.ty)];
  if (!mat.passable || !mat.buildable) return `Can't build on ${cap(mat.name)}`;
  const h = state.buildings.find((b: any) => b.type === 'hall');
  if (m.def.id !== 'hall') {
    if (!h) return 'Build the Racket Hall first — everything roots to it';
    const d = Math.max(Math.abs(m.tx - h.tx), Math.abs(m.ty - h.ty));
    if (d > CFG.build.maxDistFromHall) return `Too far from the Hall (max ${CFG.build.maxDistFromHall} tiles)`;
  }
  return "Can't build there";
}
```
`cap = (s: string) => s[0].toUpperCase() + s.slice(1)` — display-only capitalization (see the
landmine note above; `mat.name` itself is never mutated). New import: `MATERIALS` from
`'../data/materials'`.

## Learning notes
- Dual-grid autotiling: the border doesn't belong to either tile — it belongs to *both*, so you
  render it by asking "what's on each side" instead of "what am I." The `heightClass`-then-id
  stacking rule is the generic function ROADMAP asked for: content (which material outranks which)
  stays data, the blend math is generic.
- Painter's-algorithm depth: a cliff is not geometry, it's the *claim* that this pixel is a wall
  seen edge-on — shading (dark below, light rim above) is the entire trick. Games have used this
  since sprites were 8×8.
- The foam overlay's `{sprite, tex}`-per-chunk pattern, orthogonal to the base bake, is the same
  shape R2's fire glow needs — building it once here means R2 doesn't invent a second renderer.
