## Part 1 — Browser reality (facts the design must respect)

| Fact | Consequence in current code |
|---|---|
| `navigator.connection.type` is exposed **only on Android/ChromeOS**. Desktop Chrome: always `undefined`. | Every desktop player is permanently `'unknown'` → `biomeForConnection` returns **Loopback forever**; connection-type rifts can never fire on a PC. The N2 biome design as written is unreachable by its own developer. |
| `connection.rtt` is **quantized to 25 ms buckets** (0, 25, 50, …) and `0` means "unknown". | `getDamageMul()`'s ≤20 ms → 1.4× tier is **unreachable** (0 is treated as invalid → fallback 50). Observable tiers collapse to 25 → 1.2×, 50 → 1.05×, ≥75 → 1.0×. |
| `connection.downlink` is **capped at 10 Mbps** (anti-fingerprinting). | Gold-rate transform `0.5 + dl/20` tops out at **1.0×** — the "fast internet = territory thrives" upside cannot occur; the comment's "50 Mbps = 1.5×" is impossible. |
| `effectiveType` is `'4g'` on virtually every desktop/broadband connection (no `'5g'` exists in the spec). | `enemyScale` is a constant 1.0× for almost all players. |
| First `fetch()` to a host pays DNS+TCP+TLS (~3–10× slower); later fetches reuse the pooled connection. `cache:'no-store'` does not prevent connection reuse. | Beacon "resonance crits" (<30 ms echo) are mostly a function of **route warmth**, not geography — first contact with a beacon essentially never crits, repeat contact often does. Hidden mechanic; embrace or neutralize it (F3). |
| Ad blockers (uBlock etc.) commonly block `yandex.ru`, `baidu.com`, tracker-listed favicons. | Several beacons will read "unreachable" for a chunk of real players — acceptable (it's flavor), but don't let core mechanics depend on any single beacon. |
| `fetch()` favicon timing measures the full HTTP round trip, not ICMP RTT. | Fine for gameplay — just never label it "ping" in docs; it's "echo". |

## Part 2 — Design decisions (user-approved 2026-07-16, FINAL)

**D1 — Realms come from the beacon latency profile, not `connection.type`.**
Derive the realm from measured echoes to the discovered beacon network — e.g. rolling median
echo + variance across recently-probed beacons. Sketch (tune freely): median <80 ms & stable →
civilized realm; median <80 ms & high variance → wild realm; median ≥80 ms or very unstable →
chaos realm. **Loopback is reserved for actually-offline.** Real `connection.type` switches
(Android only) may still trigger bonus rifts. A realm-profile change (sustained band crossing,
debounced ≥30 s) becomes the rift trigger for N2.

**D2 — Real clock sets the starting phase only.**
Your run is "born" at the real time of day (born at dusk vs dawn — personal, on-theme), then
the cycle runs at game speed so every session gets full day/night loops and hordes. Delete the
per-tick nudge toward wall clock.

**D3 — Flavor is mystical resonance; the physical world stays physical.**
Wood is wood, trees are trees. The network theme lives in the overlay systems: Pulse/Flow/Flux,
beacons, echoes, rifts, realms, resonance crits (i.e., what the code already does). The N2
brief's item/skill/building rename tables (Wood → "Copper Packet" etc.) are **dropped**.

**D4 — Global sim speed clamps to 0.85–1.15×.**
Felt but never dominant. The drama belongs to discrete events (rifts, flux surges, resonance
crits, damage mul), not time dilation.

## Part 3 — Fix list (implement in order, one commit each)

**F1 — Decontaminate jitter.** `src/game/systems/network.ts`
`rttSamples` mixes quantized `connection.rtt` values (~25/50 ms, near-constant) with full HTTP
echo latencies (100–500 ms) pushed by `tryEndpoints()`. One 300 ms outlier in the 30-sample
mean-absolute-successive-difference window adds ~+17 ms of "jitter"; with the 10 s endpoint
poll, jitter >25 ms is the **steady state** on a quiet desktop — which makes economy.ts's flux
surge (`jitter > 25` → `+jitter*0.6` gold, `economy.ts:33`) a permanent gold faucet and spams
"⚠ turbulent" logs. Fix: two separate buffers — `jitter` computed ONLY from successive
`connection.rtt` deltas; new `echoJitter` metric computed ONLY from successive echoes to the
SAME beacon URL. Re-key flux surge to `echoJitter` with a rebalanced threshold, and verify a
5-minute idle desktop session produces zero flux surges.

**F2 — Rewire realm selection per D1.** `src/game/data/biomes.ts`, `src/game/data/network.ts`,
`src/game/systems/network.ts`
Add `realmProfile()` (median + variance over recent echoes) and `biomeForProfile()`;
`biomeForConnection` stays only as the Android bonus path. Fix the `'unknown'` inconsistency
while there: `NET_METRICS`' connectionType row and `packForCore()` map `'unknown'` → 0
(ethernet) but `biomeForConnection('unknown')` → Loopback — after D1, `'unknown'` must mean
"no signal, use profile", and Loopback must mean "offline". Rift = debounced realm-profile band
crossing (≥30 s cooldown as already implemented).

**F3 — Throttle the attack volley + neutralize route warmth.** `src/game/systems/network.ts`
`probeAttackVolley(3)` fires 3 HTTP requests on EVERY swing, no cooldown — spam-clicking
generates multi-Hz traffic to third-party news sites (rude, battery-hostile, ad-block bait).
Fix: one echo per swing, full volley at most once per ~1.5 s. First-ever contact with a beacon
is marked "discovery" and can never crit (it pays the TLS handshake); only warmed-route echoes
are crit-eligible — this converts the hidden connection-reuse bias into an explicit, legible
rule ("known routes resonate").

**F4 — Rebase damage tiers on echo latency.** `src/game/systems/network.ts` `getDamageMul()`
Per the quantization fact, drive the damage multiplier from the continuous beacon-echo latency
(e.g. rolling best echo in the last 10 s) instead of `connection.rtt`, or at minimum align tier
edges to the 25 ms grid so every tier is reachable. Keep `lastSwingRtt` reporting whichever
source is used.

**F5 — Clamp sim speed per D4.** `src/game/data/network.ts` `NET_GAME_MAP` simSpeed row:
`min: 0.85, max: 1.15`, transform rescaled to that band.

**F6 — Day/night offset-only per D2.** `src/main.ts:374-393`
The current per-tick nudge (`diff × cy × 0.005` at 30 Hz) is ~30× the natural clock advance —
it slaves the game clock to wall-clock time, freezing daytime sessions in permanent day. Fix:
on boot, set `state.clock` so the cycle phase equals the real time-of-day fraction, once; delete
the nudge/snap block. Keep the `timeOfDay` metric for HUD/flavor.

**F7 — Honest gold curve.** `src/game/data/network.ts` goldRate row
Downlink observable range is (0, 10]. Rescale so the real range spans something two-sided
(e.g. 1 Mbps → 0.6×, 5 Mbps → 1.0×, 10 Mbps → 1.25×) and fix the "50 Mbps" comment.

**F8 — Gate identity probes + privacy disclosure.** `src/game/systems/network.ts` constructor,
`README.md`
`fetchIpInfo()`/`fetchGeoInfo()` currently auto-fire 2 s after boot, sending the player's IP to
ipify.org, ipapi.co, and cloudflare.com and displaying city/ISP/ASN in-game — surprising on a
public deploy, and the ROADMAP's "no privacy leak" phrasing overpromises. Fix: move identity
probes behind the first `explore` action ("scrying reveals who you are" — on-theme), add one
boot log line + README paragraph listing every external endpoint the game contacts and why.
Reword the ROADMAP non-negotiable to "no data leaves the browser except the implicit IP in
requests to the listed public endpoints; nothing is stored server-side."

**F9 — De-stale the docs.** `docs/plans/ROADMAP.md`, `docs/plans/N2-wire-realm.md`,
`docs/plans/M3.5-action-network.md`
- ROADMAP: M3.6 is marked "NEXT" but shipped as **M3.6v2** — sync-RTT damage multiplier +
  resonance crits instead of attack speed (deviation, record it); the M3.5 brief's bottom
  section describes the unshipped v1.
- N2 brief: rewrite per D1 + D3 — rift trigger = realm-profile change; drop the rename tables;
  and fix the false claim that material `onEnter/onStay/onExit` hooks are "existing R1
  infrastructure" (they don't exist — R1 materials have static props like speedMult). Split N2
  into **N2a** (theming + rifts + realm HUD, cheap) and **N2b** (material effect hooks — real
  engine work, new mechanics, own playtest gate).
- ROADMAP: note that early G1 (particles/postprocess) and early N2 (biomes/rifts) are already
  in the tree, so those milestones start from a half-built state; G1's remaining scope is
  bloom/LUT/SUBPIX-prototype/drop-shadows.
